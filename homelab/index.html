Active Directory & Security Logging Homelab

A hands-on foundation for learning Windows and Linux administration and centralized security logging.

← Back to Projects

What I built

Five virtual machines run on one Proxmox host. The lab combines an Active Directory domain, a Windows workstation, Ubuntu services and Wazuh, with a Kali VM prepared for future practice.

Windows Server
Active Directory Domain Services and DNS, with organizational units, users and groups.
Windows 11
A domain-joined workstation with an audit baseline applied through Group Policy.
Ubuntu DNS host
Pi-hole DNS filtering and a Wazuh agent.
Ubuntu Wazuh host
Wazuh server, indexer and dashboard for centralized event collection.
Kali Linux
A practice VM prepared for future exercises against my own lab systems.

Administration and logging

The domain controller handles domain DNS queries and forwards external requests to Pi-hole. Conditional forwarding sends domain lookups from the DNS filter back to the domain controller.

I configured Windows auditing, command-line process-creation events, PowerShell logging and Sysmon. A Group Policy linked to the workstation organizational unit applies the workstation audit settings; the domain controller has separately configured auditing.

What I checked during setup

My build notes record successful collection of Windows Security, Sysmon and PowerShell events in Wazuh. Agents were enrolled on the domain controller, Windows workstation and Ubuntu DNS host. The Wazuh manager also monitors itself.

I worked through DNS selection that prevented the workstation from joining the domain and a Linux storage-allocation issue that interrupted the Wazuh installation.

Next steps

The completed work is infrastructure and logging setup. Documented detection exercises and alert tuning are next: generate a known test event in the lab, trace its logs and explain what the monitoring shows. Network segmentation and VPN access are future additions.
